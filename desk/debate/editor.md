# 主編辯論紀錄：單一 Grokbot 每日 feature + culture 的誠實產量

日期：2026-09-19
角色：chief editor
鎖定目標：daily RSS, 3 packs。Briefing 可短。Feature 與 culture 必須是讀過原文後寫成的完整繁體中文正式報導。Culture 限 restoration / old film / literature / design / history / music / ideas。硬事實核對。禁止 Cloudflare Workers AI 寫作。

## 協議原文

PROTOCOL.txt：
- feature = 正式報導。1 或 2 篇完整文章。每篇 1200–2800 中文字。
- culture = 正式報導或評論。1 或 2 篇。同樣長度。

ARTICLE_SPEC.txt：完整可讀文章必須具備「發生了什麼、場景或機制、時間深度、有性質的數字、具名機構或人物、爭議、知識邊界」。

## 現況觀察

2026-09-18 與 2026-09-19 的 feature.md / culture.md 皆為多則短條，整檔字數明顯低於單篇 1200 字門檻，屬於簡報級而非正式報導。

## 論證

一次完整流程必須：
1. 廣泛蒐集多語標題。
2. 實際開啟並閱讀 8–12 篇原文（含付費牆與長文）。
3. 對硬事實做多源交叉核對。
4. 以台灣用語繁體中文重寫成完整報導。

在真實注意力與 token 限制下，認真完成上述四步後，能穩定產出且仍符合「完整 + 可驗證」標準的數量，是 feature 1 篇 + culture 1 篇（每篇目標 1200–2000 字）。

若強制每日 2+2，幾乎必然出現：
- 把簡報條目偽裝成正式報導，或
- 縮短閱讀深度、放寬事實核對。

兩者都直接違反鎖定目標。

## 結論

單一 Grokbot 每日一輪的誠實產出，應固定為：

- feature：1 篇完整正式報導（目標 1200–2000 中文字）
- culture：1 篇完整正式報導或評論（同樣 1200–2000 中文字）

必要時可在其中一篇再加一篇較短但仍完整的第二篇，但絕不以「2+2」為常態。
簡報可短；feature 與 culture 寧可少而完整，也不要多而半成品。
這才是在讀原文、硬事實核對、繁中重寫三道工序下，不會自我欺騙的產量。
